## Java 12

JDK 12 được phát hành vào ngày 19/03/2019, đây là một phiên bản không phải LTS (non-LTS).

Bài viết này sẽ chọn lọc và giới thiệu chi tiết một số tính năng mới tương đối quan trọng trong đó:

- [JEP 189: Shenandoah: A Low-Pause-Time Garbage Collector (Experimental) (Bộ thu gom rác độ trễ thấp Shenandoah, thử nghiệm)](https://openjdk.org/jeps/189)
- [JEP 325: Switch Expressions (Preview) (Biểu thức switch, tính năng xem trước)](https://openjdk.org/jeps/325)
- [JEP 334: JVM Constants API (API hằng số JVM)](https://openjdk.org/jeps/334)
- [JEP 344: Abortable Mixed Collections for G1 (Tập hợp thu gom hỗn hợp có thể hủy bỏ cho G1)](https://openjdk.org/jeps/344)
- [JEP 346: Promptly Return Unused Committed Memory (Trả lại kịp thời bộ nhớ đã cấp phát nhưng chưa sử dụng cho G1)](https://openjdk.org/jeps/346)

Biểu đồ dưới đây thể hiện số lượng tính năng mới và thời gian phát hành của từng phiên bản từ JDK 8 đến JDK 25:

![Số lượng tính năng mới và thời gian phát hành của từng phiên bản từ JDK 8 đến JDK 25](/media/jg/ext/oss.javaguide.cn/javaguide/java/new-features/jdk8-jdk24-a3e32dd5.png)

### JEP 189: Shenandoah (Bộ thu gom rác độ trễ thấp, thử nghiệm)

Shenandoah là một bộ thu gom rác có thời gian tạm dừng thấp (low-pause) do Red Hat dẫn đầu phát triển, hướng tới mục tiêu giữ thời gian tạm dừng ngắn và tương đối độc lập với kích thước Heap ngay cả khi Heap lớn.

So với ZGC được mã nguồn mở từ Java 11 (cần nâng cấp lên JDK 11 mới sử dụng được), Shenandoah GC có phiên bản ổn định trên JDK 8u, nên trong bối cảnh Java 8 vẫn chiếm thị phần chủ yếu, tính khả thi để áp dụng vào thực tế của Shenandoah cao hơn.

### JEP 344 & JEP 346: Tối ưu bộ thu gom G1

Java 12 mang đến hai cải tiến cho bộ thu gom rác mặc định G1:

- **Tập hợp thu gom hỗn hợp có thể hủy bỏ (Abortable Mixed Collections)**: Cài đặt của JEP 344. Để đạt được mục tiêu thời gian tạm dừng (pause-time goal) do người dùng cung cấp, JEP 344 tách tập các vùng nhớ cần thu hồi (tập thu gom hỗn hợp) thành phần bắt buộc và phần tùy chọn, cho phép bộ thu gom rác G1 có thể hủy bỏ quá trình thu gom. G1 có thể hủy việc thu hồi phần tùy chọn nhằm đạt mục tiêu thời gian tạm dừng.
- **Trả lại kịp thời bộ nhớ đã cấp phát nhưng chưa sử dụng**: Cài đặt của JEP 346, tăng cường G1 GC để tự động trả lại bộ nhớ Java Heap cho hệ điều hành khi rảnh rỗi.

### JEP 334: JVM Constants API (API hằng số JVM)

Giới thiệu một API để mô hình hóa các mô tả danh nghĩa (nominal descriptions) cho các thành phần class-file và runtime quan trọng, đặc biệt là các hằng số có thể nạp từ Constant Pool.

API này cung cấp một tập hợp các interface và lớp tiện ích để biểu diễn và thao tác với các mục trong Constant Pool của file class. Nó chủ yếu bao gồm:

- **Interface mô tả hằng số**: Interface `ConstantDesc` và các subinterface của nó, dùng để mô tả các kiểu hằng số khác nhau
- **Kiểu giá trị hằng số**: `ClassDesc`, `MethodTypeDesc`, `MethodHandleDesc`, `DynamicConstantDesc`, v.v.
- **Bootstrap method**: Hỗ trợ lệnh `invokedynamic` và các bootstrap method cho hằng số động

API này chủ yếu nhằm hỗ trợ các kịch bản sau:

1. **Thao tác class file**: Cung cấp một cách chuẩn hóa để mô tả và thao tác với Constant Pool trong file class
2. **Sinh bytecode**: Đơn giản hóa sự tương tác giữa các framework sinh bytecode (như ASM) và mã nguồn Java
3. **Tăng cường Reflection**: Giúp các thao tác Reflection an toàn kiểu hơn và giàu khả năng biểu đạt hơn
4. **Công cụ trình biên dịch**: Cung cấp lớp trừu tượng tốt hơn cho trình biên dịch và các công cụ sinh mã

API này là một cải tiến tầng dưới quan trọng trong Java 12, đặt nền móng cho các tính năng thao tác bytecode và trình biên dịch sau này.

### JEP 325: Switch Expressions (Biểu thức switch, xem trước)

Cú pháp `switch` truyền thống tồn tại vấn đề dễ viết thiếu `break`, và xét về khía cạnh sự gọn gàng của code, nhiều câu lệnh `break` về bản chất cũng là một sự lặp lại.

Java 12 nâng cấp biểu thức `switch`, sử dụng cú pháp giống lambda cho khối thực thi sau khi khớp điều kiện, không cần viết thêm `break`.

```java
switch (day) {
    case MONDAY, FRIDAY, SUNDAY -> System.out.println(6);
    case TUESDAY                -> System.out.println(7);
    case THURSDAY, SATURDAY     -> System.out.println(8);
    case WEDNESDAY              -> System.out.println(9);
}
```

### JEP 351: ZGC (Giải phóng bộ nhớ không sử dụng)

ZGC được giới thiệu thử nghiệm trong Java 11 gặp vấn đề trong thực tế là không chủ động giải phóng bộ nhớ chưa sử dụng trả về cho hệ điều hành.

ZGC Heap bao gồm một tập hợp các vùng Heap gọi là ZPages. Khi các vùng ZPages được làm trống trong một chu kỳ GC, chúng sẽ được giải phóng và đưa về bộ nhớ đệm trang **ZPageCache**, trong đó các ZPages được sắp xếp theo thứ tự sử dụng ít gần đây nhất (LRU) và phân loại theo kích thước.

Trong Java 13, ZGC sẽ trả lại cho hệ điều hành các trang được xác định là không được sử dụng trong thời gian dài, nhờ đó các tiến trình khác có thể tái sử dụng chúng.

### JEP 350: Dynamic CDS Archives (Lưu trữ CDS động)

Trong Java 13, tính năng Application Class-Data Sharing (AppCDS) được giới thiệu từ Java 10 tiếp tục được đơn giản hóa, cải thiện và mở rộng, cụ thể là: **cho phép thực hiện lưu trữ lớp động (dynamic archiving) khi ứng dụng Java kết thúc thực thi**. Các lớp có thể được lưu trữ bao gồm toàn bộ các lớp ứng dụng và thư viện tham chiếu đã được nạp nhưng không thuộc bản lưu trữ CDS cơ sở mặc định.

Điều này giúp nâng cao tính khả dụng của Application Class-Data Sharing ([AppCDS](https://openjdk.java.net/jeps/310)). Người dùng không cần chạy thử nghiệm trước để tạo danh sách lớp cho từng ứng dụng nữa.

```bash
java -XX:ArchiveClassesAtExit=my_app_cds.jsa -cp my_app.jar
java -XX:SharedArchiveFile=my_app_cds.jsa -cp my_app.jar
```

### JEP 355: Text Blocks (Xem trước)

Nhằm giải quyết vấn đề khi định nghĩa chuỗi nhiều dòng trong Java trước đây chỉ có thể lách bằng ký tự escape xuống dòng hoặc toán tử nối chuỗi, Java 13 đưa vào **ba dấu ngoặc kép liên tiếp** để định nghĩa văn bản nhiều dòng.

Java 13 hỗ trợ mọi nội dung nằm giữa hai ký hiệu `"""` sẽ được hiểu là một phần của chuỗi, bao gồm cả ký tự xuống dòng. Lưu ý: "hai" ở đây cần hiểu là "một cặp", tức một ở đầu và một ở cuối.

Cách viết HTML trước khi hỗ trợ Text Blocks:

```java
String json ="{\n" +
              "   \"name\":\"mkyong\",\n" +
              "   \"age\":38\n" +
              "}\n";
```

Cách viết HTML sau khi hỗ trợ Text Blocks:

```java
 String json = """
                {
                    "name":"mkyong",
                    "age":38
                }
                """;
```

Cách viết SQL trước khi hỗ trợ Text Blocks:

```sql
String query = "SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`\n" +
               "WHERE `CITY` = 'INDIANAPOLIS'\n" +
               "ORDER BY `EMP_ID`, `LAST_NAME`;\n";
```

Cách viết SQL sau khi hỗ trợ Text Blocks:

```sql
String query = """
               SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`
               WHERE `CITY` = 'INDIANAPOLIS'
               ORDER BY `EMP_ID`, `LAST_NAME`;
               """;
```

Giới thiệu về các phương thức liên quan đến Text Blocks (`formatted()`, `stripIndent()`, `translateEscapes()`) vui lòng xem mục [Cải tiến API - Cải tiến String (Các phương thức liên quan đến Text Block)](#cai-tien-string-cac-phuong-thuc-lien-quan-den-text-block) trong bài viết này.

### JEP 354: Switch Expressions (Biểu thức switch, xem trước lần hai)

Biểu thức `Switch` có thêm từ khóa `yield` để thoát khỏi khối `Switch`, chủ yếu dùng để trả về một giá trị.

Điểm khác biệt giữa `yield` và `return` là: `return` kết thúc phương thức hiện tại và trả về kết quả, còn `yield` kết thúc nhánh biểu thức `switch` hiện tại và tạo ra giá trị cho biểu thức đó. Biểu thức `switch` phải bao phủ mọi đầu vào có thể, nhưng khi đã liệt kê hết mọi giá trị có thể thì không nhất thiết phải có nhánh `default`.

```java
 private static String descLanguage(String name) {
        return switch (name) {
            case "Java": yield "object-oriented, platform independent and secured";
            case "Ruby": yield "a programmer's best friend";
            default: yield name +" is a good language";
        };
 }
```

## Cải tiến API

Không phải tất cả các thay đổi API đều được phát hành thông qua JEP (Java Enhancement Proposal).

Trong quy trình phát triển của JDK: **JEP** thường được dùng cho các thay đổi lớn, chẳng hạn như giới thiệu tính năng ngôn ngữ mới (như biểu thức `switch`), cơ chế JVM mới (như ZGC) hoặc tái cấu trúc thư viện quy mô lớn. Những thao tác như thêm vài phương thức vào các lớp hiện có (ví dụ `String.indent()`) thường được xem là bảo trì thư viện thông thường. Chúng được các lập trình viên JDK gửi và đánh giá trực tiếp thông qua ticket trên **JBS (JDK Bug System)**, sau đó phát hành thẳng cùng phiên bản.

### Cải tiến String

Java 12 bổ sung thêm hai phương thức xử lý chuỗi mới.

#### indent() - Phương thức thụt lề

Phương thức `indent()` có thể thực hiện thụt lề cho chuỗi.

```java
String text = "Java";
// Thụt lề 4 khoảng trắng
text = text.indent(4);
System.out.println(text);
text = text.indent(-10);
System.out.println(text);
```

Kết quả đầu ra:

```plain
     Java
Java
```

#### transform() - Phương thức chuyển đổi

Phương thức `transform()` có thể dùng để biến đổi một chuỗi chỉ định.

```java
String result = "foo".transform(input -> input + " bar");
System.out.println(result); // foo bar
```

### Cải tiến Files

Java 12 bổ sung phương thức `mismatch()` để so sánh hai file:

```java
public static long mismatch(Path path, Path path2) throws IOException
```

Phương thức `mismatch()` dùng để so sánh hai file và trả về vị trí của byte đầu tiên không khớp, nếu hai file giống nhau thì trả về `-1L`.

Ví dụ code (trường hợp hai file có nội dung giống nhau):

```java
Path filePath1 = Files.createTempFile("file1", ".txt");
Path filePath2 = Files.createTempFile("file2", ".txt");
Files.writeString(filePath1, "Java 12 Article");
Files.writeString(filePath2, "Java 12 Article");

long mismatch = Files.mismatch(filePath1, filePath2);
assertEquals(-1, mismatch);
```

Ví dụ code (trường hợp hai file có nội dung khác nhau):

```java
Path filePath3 = Files.createTempFile("file3", ".txt");
Path filePath4 = Files.createTempFile("file4", ".txt");
Files.writeString(filePath3, "Java 12 Article");
Files.writeString(filePath4, "Java 12 Tutorial");

long mismatch = Files.mismatch(filePath3, filePath4);
assertEquals(8, mismatch);
```

### Cải tiến NumberFormat

Trong Java 12, `NumberFormat` bổ sung hỗ trợ định dạng các con số theo dạng rút gọn (compact number formatting):

```java
NumberFormat fmt = NumberFormat.getCompactNumberInstance(Locale.US, NumberFormat.Style.SHORT);
String result = fmt.format(1000);
System.out.println(result);
```

Kết quả đầu ra:

```plain
1K
```

### Cải tiến Socket API

Java 13 đã viết lại tầng dưới của Socket API. `NioSocketImpl` là sự thay thế trực tiếp cho `PlainSocketImpl`, sử dụng các khóa thuộc gói `java.util.concurrent` thay vì các phương thức `synchronized`. Nếu muốn dùng lại bản cài đặt cũ, hãy sử dụng tham số `-Djdk.net.usePlainSocketImpl=true`.

Ngoài ra, trong Java 13, bản cài đặt Socket mới được sử dụng làm mặc định.

```java
public final class NioSocketImpl extends SocketImpl implements PlatformSocketImpl {
}
```

### Cải tiến FileSystems

Trong Java 13, lớp `FileSystems` được bổ sung ba phương thức mới sau đây nhằm giúp sử dụng dễ dàng hơn các trình cung cấp hệ thống tệp coi nội dung của một file như một hệ thống tệp:

- `newFileSystem(Path)`
- `newFileSystem(Path, Map<String, ?>)`
- `newFileSystem(Path, Map<String, ?>, ClassLoader)`

### Cải tiến String (Các phương thức liên quan đến Text Block)

Java 13 giới thiệu tính năng xem trước Text Blocks, lớp `String` bổ sung thêm 3 phương thức mới để thao tác với Text Blocks:

- `formatted(Object... args)`: Tương tự phương thức `format()` của `String`. Được thêm vào để hỗ trợ định dạng cho Text Blocks.
- `stripIndent()`: Dùng để loại bỏ khoảng trắng ở đầu và cuối mỗi dòng trong Text Block.
- `translateEscapes()`: Chuyển đổi các chuỗi escape như _"\\\t"_ thành _"\t"_.

Do Text Blocks là một tính năng xem trước và có thể bị xóa ở các phiên bản tương lai, các phương thức mới này được đánh dấu là deprecated.

```java
@Deprecated(forRemoval=true, since="13")
public String stripIndent() {
}
@Deprecated(forRemoval=true, since="13")
public String formatted(Object... args) {

}
@Deprecated(forRemoval=true, since="13")
public String translateEscapes() {
}
```

Để biết giới thiệu chi tiết về Text Blocks, vui lòng xem phần [JEP 355: Text Blocks (Xem trước)](#jep-355-text-blocks-xem-truoc) trong bài viết này.

## Bổ sung

### Về tính năng xem trước (Preview Features)

Trước tiên hãy xem nguyên văn từ trang web chính thức của Oracle: `This is a preview feature, which is a feature whose design, specification, and implementation are complete, but is not permanent, which means that the feature may exist in a different form or not at all in future JDK releases. To compile and run code that contains preview features, you must specify additional command-line options.`

Đây là một tính năng xem trước: thiết kế, đặc tả và cài đặt của tính năng đã hoàn chỉnh nhưng không phải vĩnh viễn, nghĩa là tính năng này có thể tồn tại ở một hình thức khác hoặc không tồn tại chút nào trong các bản phát hành JDK tương lai. Để biên dịch và chạy code có chứa tính năng xem trước, bạn phải chỉ định thêm các tùy chọn dòng lệnh bổ sung.

Lấy biểu thức `switch` làm ví dụ, nó bắt đầu ở trạng thái xem trước từ Java 12, tiếp tục được điều chỉnh trong Java 13 và trở thành tính năng ngôn ngữ chính thức trong Java 14. Sau khi chính thức hóa, cú pháp và ngữ nghĩa của nó thuộc về đặc tả Java SE, không cần phải bật chế độ xem trước nữa.

Một mặt có thể thấy thái độ thận trọng, nghiêm túc của JDK với tư cách là một nền tảng chuẩn khi bổ sung tính năng mới; mặt khác theo quan điểm cá nhân, đối với các tính năng xem trước vẫn nên áp dụng thái độ sử dụng cân nhắc. Thiết kế và hiện thực hóa một tính năng thì tương đối dễ, nhưng giá trị thực tế của nó vẫn cần được kiểm chứng trong quá trình sử dụng.

### Tối ưu máy ảo JVM

Mỗi lần phát hành phiên bản Java mới đều đi kèm với các tối ưu hóa cho máy ảo JVM, bao gồm cải tiến các thuật toán Garbage Collection hiện có, giới thiệu các thuật toán Garbage Collection mới, loại bỏ các thuật toán thu gom rác cũ không còn phù hợp với hiện nay, v.v.

Định hướng tối ưu tổng thể là **hiệu năng Garbage Collection hiệu quả cao và độ trễ thấp**.

Lập trình viên ứng dụng hằng ngày có thể quan tâm nhiều hơn đến các tính năng cú pháp mới, nhưng đứng ở góc độ một doanh nghiệp, khi cân nhắc có nâng cấp nền tảng Java hay không thì điều được quan tâm hơn lại là **những cải tiến ở tầng runtime của JVM**.
