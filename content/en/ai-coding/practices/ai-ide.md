## AI Coding IDE Usage Tips

### Have you used any AI coding IDEs? What are your impressions?

The overall impression today: AI coding capabilities are advancing rapidly. It has evolved from simple code completion a few years ago into an engineering assistant capable of deep collaboration.

I have summarized my own methodology:

1. When taking over complex projects or modules, I never instruct the AI to write code right away. Instead, I first have Cursor analyze the entire codebase to generate documentation outlining core architecture, module responsibilities, and data flows. This step is pivotal because it dictates the quality of subsequent collaboration. Only when the AI and I share a unified understanding of the project will subsequent outputs remain stable and high-quality.
2. For each independent development task, start a fresh conversation and supply necessary context, including requirement background, involved modules, and constraints. This mitigates context pollution, yielding far more precise generated code.
3. Regularly prune redundant implementations and obsolete code. Outdated code misleads AI judgment and inflates context noise.

### Core Principles of AI-Assisted Programming

AI serves as a powerful knowledge base and auxiliary tool that helps us implement features quickly and learn new concepts. However, if one relies completely on AI to write code without understanding underlying principles, their technical capabilities may atrophy.

Several guiding principles:

- Code generated by AI must undergo manual review.
- Rewrite critical logic personally when necessary.
- Core execution paths must undergo stress testing and edge-case testing.

The goal is boosting productivity without compromising technical mastery.

### ⭐ Cursor Practical Tips

> Using Cursor as an example here; other AI IDEs follow similar patterns.

1. **Clarify architecture before acting**: Whether writing code manually or having AI generate it, always define requirements, overall architecture, and module boundaries first. Coding under architectural ambiguity frequently leads to duplicate implementations or conflicting responsibilities, inflating downstream modification costs.
2. **Single Chat focused on a single feature**: Open a new Chat for new features or substantial refactoring, introducing project structure summaries or key documentation at the beginning as context. This prevents interference from conversational history.
3. **Draft guidelines post-implementation**: Have the AI summarize the implementation process and abstract reusable steps, such as standard flows for adding endpoints or unified approaches for file exports. These can be swiftly reused in future similar requirements.
4. **Do not blindly trust AI; actively review**: AI is merely an assistant. Once code is generated, review it carefully, understand the mechanics, and optimize questionable sections.
5. **Periodically delete useless code**: Clean up obsolete code to reduce hallucinations and context interference, improving development velocity.
6. **Leverage configuration files**: `.cursorrules` defines rules, styles, and common snippets for AI generation; `.cursorignore` protects sensitive or core files from AI modification.
7. **Continuously maintain documentation**: After major architectural shifts, have the AI synchronously update docs and document lessons learned.
8. **Have AI "study" the project first**: In large codebases, have Cursor analyze the repository first to generate structural docs detailing architecture, directory responsibilities, and core classes to serve as foundational context for subsequent development.

### ⭐ Claude Code Practical Tips

1. **The context window is your most precious resource**—all tips essentially help you use this whiteboard more efficiently.
2. **Plan before executing**—Plan Mode is an investment in downstream execution time.
3. **`CLAUDE.md` self-evolution**—turn manual corrections into rules, making the AI progressively smoother to work with.
4. **Parallelism is your greatest productivity lever**—multiple instances + Git Worktrees + Subagents.
5. **Verification over trust**—provide Claude with explicit acceptance criteria and let it verify itself.
6. **`/compact` is more effective than repeated corrections**—once context becomes polluted, compressing or clearing it to start fresh is superior.

## The Impact of AI Coding on Developers

### How do you view AI's impact on backend development?

AI will not replace backend engineers, but it will fundamentally reshape their working paradigms and skill structures.

AI helps us handle repetitive, boilerplate tasks:

- **At the coding level**: AI tools excel at generating **boilerplate code**. Efficiency in writing CRUD, unit tests, and glue code can increase by 50%~70%. However, regarding **distributed constraints** (e.g., distributed lock renewal/lease expiration, message queue exactly-once semantics, API idempotency design), AI carries a significant **"hallucination" risk**—it frequently provides only Happy Path code, neglecting exception compensation logic, race conditions, and distributed transaction boundaries in production.
- **At the architectural level**: AI is fostering new application paradigms, such as Agent-driven automated business processes, where backends must provide more flexible, atomic capability interfaces. Traditional monolithic interfaces are gradually decomposing into atomic capabilities consumable by AI.
- **At the ops and troubleshooting level**: AI can assist in analyzing logs, monitoring alerts, and even forecasting system bottlenecks. For example, AIOps-based tools can automatically analyze anomalous log patterns to identify root causes.

AI empowers backend engineers to concentrate on business modeling, complex system design, and architectural decision-making—the more creative and vital core pursuits.

In my own work, I frequently discuss business and technical designs with AI; it consistently offers valuable inspiration—particularly during requirement decomposition and technical evaluations, AI brings multi-angled perspectives.

From practical experience, AI-assisted coding capabilities span two dimensions:

- **0-to-1 Planning and Delivery**: Given requirement descriptions, AI can autonomously conduct technical evaluations and architectural designs, ideal for rapid concept validation, though proposals still require human review.
- **Incremental Optimization of Existing Code**: In complex established codebases, AI can comprehend existing architectures, pinpoint issues, and execute optimizations. However, situations where AI proposals "look correct" yet crash in production remain common.

### Core Competencies for Frontend and Backend Developers Have Shifted

Truth be told, core competencies for both frontend and backend engineers have fundamentally changed.

Previously, frontend competed on typing speed and pixel-perfect fidelity, while backend competed on CRUD and interview trivia ("baguwen"). Today, AI handles all of these rapidly, tirelessly, consuming only tokens. The page layout that took you half a day to build, AI finishes in 10 minutes; the CRUD APIs that took you two hours, AI hands in within three minutes. It is not that these skills are useless, but they are no longer scarce—and therefore, no longer premium.

Frontend experienced the most immediate disruption. Page rendering, component authoring, and CSS styling are heavily patterned—precisely where LLMs shine. Yet what died was not the frontend discipline itself, but the frontend developer who "only knows how to write pages."

Competitive frontend developers diverge in two directions: either dive deep—performance optimization, rendering pipeline profiling, and engineering infrastructure, which AI cannot substitute; or tackle high complexity—WebGL, large-scale data visualization, and cross-platform native internals, where AI generates poor quality, forming a defensible moat.

Backend is slightly better off, but complacency is dangerous. AI writes single endpoints exceptionally well; its Achilles' heel is systemic thinking—service decomposition, data model design, cache consistency guarantees, and capacity bottleneck prediction. These demand holistic judgment combining business scenarios and technical debt; AI proposals often "look correct" but stumble in production.

Backend core competencies are shifting toward system design, stability governance, and complex domain modeling.

Regardless of frontend or backend, one fundamental skill is mandatory: collaborating efficiently with AI. This does not mean merely knowing how to use ChatGPT, but breaking down problems, guiding outputs, discerning result reliability, and identifying security hazards. You have evolved from a "code writer" into an "AI technical auditor."

Those who generate code without inspecting logic gain short-term speed while planting long-term landmines—when production fails, they can only repeatedly query AI, lacking independent diagnostic intuition.

### Will AI Eliminate Junior Programmers?

In the short term, it will not eliminate them, but it will thoroughly overhaul the capability expectations of junior engineers.

Previously, the value of junior engineers rested on:

- Writing CRUD operations
- Implementing basic APIs
- Writing SQL queries
- Creating basic utility classes/configs

Today, AI executes these tasks proficiently, often faster and with fewer errors. Yet junior programmers will not be rendered obsolete; the point of value creation has simply migrated.

Future junior engineers will need:

- **Requirement decomposition capability**: Translating ambiguous business demands into structured technical tasks.
- **Domain comprehension**: Grasping domain models and business rules, rather than merely "translating requirements."
- **Architectural awareness**: Understanding overall system architecture and where their code fits within it.
- **Prompt articulation**: Precisely describing problems to extract high-quality answers from AI.

AI lowers the barrier to coding, but raises the bar for "comprehension." Future junior engineers will act more like "AI coordinators" than pure "code writers."

From a hiring perspective, demand for pure manual coding will decline, but demand for engineers who can "leverage AI to rapidly deliver business value" will surge.

### What Is the Greatest Risk Brought by AI?

I believe risks exist across three primary layers:

**1. Technical Skill Atrophy**

Excessive reliance on AI leads to degradation of an engineer's technical depth, particularly:

- **Declining debugging proficiency**: Becoming accustomed to having AI troubleshoot, while personal grasp of underlying mechanics weakens.
- **Diminished code taste**: Weakened ability to differentiate "clean code" from "code smells," eventually losing the standard for quality code.
- **Architectural atrophy**: Focusing exclusively on feature delivery while ignoring architectural hygiene and extensibility.

**2. Architectural Drift and Loss of Control**

AI-generated code focuses predominantly on "making the current feature work," easily neglecting long-term architectural health. This largely stems from **Vibe Coding**—relying on vague intent and letting AI "freeform."

- **Blurred module boundaries**: AI leans toward "finishing features quickly," often mixing multiple concerns into a single module. Clearly define bounded contexts (DDD style) prior to coding, constraining AI generation via predefined interface contracts.

- **Accumulation of technical debt**: In the rush to deliver, AI may resort to hardcoding, bypassing standard exception handling, or introducing cyclic dependencies. Such debt drastically escalates refactoring costs as the codebase grows.

- **Inconsistent coding styles**: Code generated across disparate chat sessions often uses conflicting naming conventions, error handling paradigms, and log formats. Employ **Spec Coding** to define unified technical standards and styles (such as `.cursorrules`), ensuring AI consistently operates under uniform guardrails.

- **Missing resource governance**: AI will not automatically account for connection pool sizing, thread pool queue capacities, or cache eviction policies. For instance, generated code might spawn unbounded thread pools, inducing OOM under traffic spikes, or use default database pool settings, creating bottlenecks under concurrency.

- **Mismatch with engineering conventions**: While AI-generated code architecture may appear sound, fitting it to existing engineering standards requires human governance. Discrepancies in file organization, style, and dependency strategies can create friction in team collaboration.

**3. Security Hazards (Demanding Special Vigilance)**

- **Code vulnerabilities**: AI may introduce security flaws, commonly including:
  - **SQL Injection**: Using string concatenation over parameterized queries
  - **XSS**: Failing to sanitize or escape user input in HTML contexts
  - **Missing authorization**: Omitting endpoint- or method-level permission checks
  - **Sensitive data leakage**: Logging secrets, tokens, or passwords
  - **Dependency vulnerabilities**: Importing third-party libraries with known CVEs
- **Data leakage**: Mishandling may leak corporate code or proprietary logic to external models (especially cloud-hosted AI APIs).
- **Supply chain risks**: Recommended packages may contain known vulnerabilities or malicious code.
- **Secret exposure**: AI-generated code may hardcode API keys, tokens, or credentials.

**4. Failure Modes in Distributed Scenarios (Particularly Hazardous)**

AI-generated code in distributed environments frequently ignores critical constraints, causing production incidents:

| Failure Mode | Common AI Oversights | Production Risk |
| --- | --- | --- |
| **Missing Idempotency** | Omitting idempotency checks, directly inserting or updating | Network timeout retries cause duplicate data or double-charging |
| **Concurrency Race Conditions** | Lacking distributed locking or CAS mechanisms | Inventory overselling, concurrent overwrite, distorted metrics |
| **Blurred Distributed Transaction Boundaries** | Unclear transaction boundaries and rollback mechanisms | Data inconsistency, partial commits, untraceable states |
| **Missing Timeouts and Fallbacks** | Default timeouts without circuit breaking or fallback logic | Cascading failures, avalanche effects, full service outages |
| **Connection Pool Leaks** | Failing to release connections or improper pool sizing | Pool exhaustion, hung services, requiring restarts to recover |

**Typical Example**: When generating "inventory deduction" code, AI typically writes `UPDATE stock SET count = count - 1 WHERE id = ?`, ignoring:

- Row locks or distributed locks under concurrent load
- Idempotency guarantees when stock is insufficient (duplicate requests should not deduct multiple times)
- Compensation mechanisms when downstream services time out
- Database connection timeouts and circuit-breaking strategies

**Mitigation Strategies**:

- **Explicit constraints** in Specs: Mandate that AI include code templates for distributed locking, idempotency validation, and compensation logic
- **Mandatory Code Review**: Scrutinize cross-service invocations, transaction boundaries, and exception handling paths
- **Chaos engineering verification**: Validate distributed resilience through automated fault injection

Enterprises must establish supporting security governance frameworks:

- **Mandatory code reviews**: AI-generated code must undergo human review.
- **Automated security scanning**: Integrate SAST/SCA tools, adding scans specifically targeting AI-induced risks (e.g., git-secrets, TruffleHog).
- **Architectural guardrails**: Complement Spec Coding with tools like ArchUnit to automate architectural constraint enforcement.

### Is AI Programming Making Developers More Exhausted and Stressed?

Someone noted: "Thought AI would make life easier? Wake up; it didn't ease your burden, it just made your boss think one developer can do the work of three."

This sounds cynical, yet reflects a genuine sentiment shared by many.

AI amplifies your individual output. Previously, writing three endpoints a day felt productive; now you can write ten, while handling architectural drafts, test cases, and documentation in parallel. Dopamine spikes, and you instinctively take on more work because AI has inflated your confidence.

Here lies the rub: as productivity surges, managerial expectations inflate even faster. The illusion of the "one-person team" prompts cutting headcount in half while working remaining staff harder. Previously you specialized in one module; now you juggle frontend, backend, multithreaded tasks, and multiple Agents concurrently.

Paradoxically, positions dwindle while workloads climb. You write code, review AI code, debug AI hallucinations, and explain to leadership why AI code collapsed in production. At times, the line blurs between whether you are using AI or AI is using you.

### ⭐ What Are the Core Competencies of a Backend Engineer in the Next 3 Years?

I believe core competencies will pivot from "code writing ability" toward the following four dimensions:

**1. System Design Capability**

While AI excels at single-function code generation, **system-level architecture** must remain engineer-driven:

- Service decomposition and module boundary demarcation
- Weighing tradeoffs between microservices and monoliths
- Data model design and consistency strategies
- API versioning and evolution strategies
- Distributed transactions and idempotency design

**2. Complex Domain Modeling Capability**

While we used to claim AI struggles with domain modeling, the landscape has evolved. AI is remarkably adept at requirement breakdown, business rule organization, and scenario simulation.

However, engineers are still essential to translate business rules into executable designs tailored to the specific project:

- Domain-Driven Design (DDD) modeling
- Business process abstraction and finite state machine design
- Bounded context demarcation

**3. Performance and Stability Governance**

AI-generated code focuses almost exclusively on functional correctness, frequently overlooking production performance characteristics:

- **P99 Latency**: AI might generate N+1 queries, unindexed SQL, or synchronous blocking calls, causing tail latencies to explode
- **Memory Escapes & Leaks**: Improper object creation and closure usage can induce frequent GC pauses or OOM
- **Connection Pool Exhaustion**: Unbounded concurrency or missing timeouts can exhaust connection pools, sparking cascading failures

Engineers must possess **performance measurement and tuning** capabilities:

- SQL slow query optimization and index design (analyzing execution plans via EXPLAIN)
- Caching strategy design and consistency guarantees (Local Cache vs. Distributed Cache)
- Asynchronous refactoring and thread pool tuning (core pool size, queue capacity, rejection policies)
- Service degradation, circuit breaking, and rate limiting (Sentinel, Hystrix applications)
- Capacity planning and elastic scaling (stress testing QPS watermarks, autoscaling)

**Verification Methods**: Once AI generates code, validate P95/P99 latency through stress testing (JMeter, Gatling) and profile memory via JVM tools (MAT, Arthas), rather than relying solely on functional tests.

**4. AI Collaboration Proficiency**

Collaborating efficiently with AI is itself a vital competitive advantage:

- **Precise requirement articulation (Prompt engineering)**: Using structured Prompts (Context - Task - Constraints - Output Format) to eliminate ambiguity
- **Decomposing problems and guiding AI**: Breaking complex tasks into independently verifiable subtasks, leveraging Chain-of-Thought reasoning
- **Evaluating AI output quality**: Establishing code review checklists covering correctness, security, performance, and maintainability
- **Security and compliance verification**: Knowing OWASP Top 10 to spot vulnerabilities in AI output
- **Mastering AI toolchains**: Proficient configuration and usage of `.cursorrules`, custom Skills, and IDE plugins

This fundamentally represents a role transition from "code author" to "AI collaboration engineer."

Future competitiveness will hinge not on "code output velocity," but on "system design quality" and "business value delivery capability."

## Summary

AI coding tools are profoundly reshaping development workflows. Tools like Cursor, Claude Code, and Trae have evolved from simple completion into deeply collaborative engineering partners.

From Prompt to Harness, in just four short years, writing code is shifting from a programmer's "craft" into an Agent's "standard operation." Some predict: "In the future, a single CTO might govern all Agents, having them produce all code, deploy, and fix bugs." While provocative, giving it serious thought reveals it is not beyond the realm of possibility.

**What truly dictates your career growth is how you wield these tools, and whether you sustain deep technical reflection throughout their use.**

Frankly, around this time last year, I felt considerable anxiety over AI advancements, especially in coding. Today, with progress accelerating so rapidly, I have actually found a sense of peace. Knowing how to write code is shifting from a core competency into basic literacy, much like how knowing Excel is not an engineering moat. The truly valuable assets are defining problems, designing architectures, governing quality, and delivering business value.

A few final tips for developers preparing for interviews:

1. **Hands-on experience is non-negotiable**: When interviewers ask about AI tools, nothing hurts more than "I heard of it but haven't used it." Even building a few small projects with Cursor beats merely reading tutorials.
2. **Establish your own methodology**: Don't just "use it"; cultivate your own insights and best practices—this is a major differentiator in interviews.
3. **Maintain a critical mindset**: Reviewing AI code is basic engineering hygiene. Demonstrating this attitude shows the interviewer you are a dependable, rigorous engineer.
4. **Follow tech trends without panicking**: AI transforms much, but system design, architectural thinking, and domain understanding will never expire.

Harnessing AI tools + maintaining independent thinking: both are indispensable. In the AI era, software engineers may well illuminate diverse industries like never before. Let's strive forward together!
