## Java 12

JDK 12 was released on March 19, 2019. It is a non-LTS release.

This article selects and explains several of the more important new features in detail:

- [JEP 189: Shenandoah: A Low-Pause-Time Garbage Collector (Experimental)](https://openjdk.org/jeps/189)

- [JEP 344: Abortable Mixed Collections for G1](https://openjdk.org/jeps/344)
- [JEP 346: Promptly Return Unused Committed Memory](https://openjdk.org/jeps/346)

### JEP 189: Shenandoah (Low-Latency Garbage Collector, Experimental)

Shenandoah is a low-pause garbage collector led and developed by Red Hat, aiming to keep pause times short and largely independent of heap size even when the heap is large.

Compared with ZGC, which was open-sourced in Java 11 (requiring an upgrade to JDK 11 to use), Shenandoah GC has a stable JDK 8u version, giving it greater practical adoption potential where Java 8 still holds a major market share.

### JEP 344 & JEP 346: G1 Collector Optimizations

Java 12 brought two updates to the default garbage collector, G1:

- **Abortable Mixed Collections**: Implemented by JEP 344. To meet user-provided pause-time goals, JEP 344 splits the set of regions to be collected (the mixed collection set) into mandatory and optional parts, enabling the G1 garbage collector to abort the collection process. G1 can abort the collection of the optional part in order to meet the pause-time goal.
- **Promptly Return Unused Committed Memory**: Implemented by JEP 346, enhancing G1 GC to automatically return Java heap memory to the operating system when idle.

### JEP 334: JVM Constants API

Introduced an API to model nominal descriptions of key class-file and run-time artifacts, in particular constants that are loadable from the constant pool.

This API provides a set of interfaces and utility classes for representing and manipulating constant pool entries in class files. It mainly includes:

- **Constant descriptor interfaces**: The `ConstantDesc` interface and its subinterfaces, used to describe various types of constants
- **Constant value types**: `ClassDesc`, `MethodTypeDesc`, `MethodHandleDesc`, `DynamicConstantDesc`, etc.
- **Bootstrap methods**: Support for the `invokedynamic` instruction and dynamic constant bootstrap methods

This API is primarily designed to support the following scenarios:

1. **Class-file manipulation**: Provides a standardized way to describe and manipulate the constant pool in class files
2. **Bytecode generation**: Simplifies the interaction between bytecode generation frameworks (such as ASM) and Java code
3. **Reflection enhancements**: Makes reflection operations more type-safe and expressive
4. **Compiler tools**: Provides better abstractions for compilers and code-generation tools

This API is an important low-level improvement in Java 12, laying the foundation for subsequent bytecode manipulation and compiler features.

### JEP 325: Switch Expressions (Preview)

Traditional `switch` syntax suffers from the problem of easily forgetting `break`, and from a code-cleanliness perspective, having multiple `break` statements is essentially repetitive.

Java 12 enhanced `switch` expressions by using a lambda-like syntax for the execution block after a condition matches, eliminating the need to write extra `break` statements.

```java
switch (day) {
    case MONDAY, FRIDAY, SUNDAY -> System.out.println(6);
    case TUESDAY                -> System.out.println(7);
    case THURSDAY, SATURDAY     -> System.out.println(8);
    case WEDNESDAY              -> System.out.println(9);
}
```

### JEP 351: ZGC (Uncommit Unused Memory)

ZGC, introduced experimentally in Java 11, had an issue in real-world usage where it did not actively release unused memory back to the operating system.

The ZGC heap consists of a set of heap regions called ZPages. When ZPages are emptied during a GC cycle, they are freed and returned to the page cache **ZPageCache**, where ZPages are organized in Least Recently Used (LRU) order and grouped by size.

In Java 13, ZGC returns pages identified as unused for a long time to the operating system so that they can be reused by other processes.

### JEP 350: Dynamic CDS Archives

Java 13 further simplified, improved, and extended Application Class-Data Sharing (AppCDS), which was introduced in Java 10. Specifically, it **allows classes to be archived dynamically when a Java application finishes executing**, where the classes eligible for archiving include all loaded application classes and library classes that do not belong to the default base CDS archive.

This improves the usability of Application Class-Data Sharing ([AppCDS](https://openjdk.java.net/jeps/310)). Users no longer need to perform trial runs to create a class list for each application.

```bash
java -XX:ArchiveClassesAtExit=my_app_cds.jsa -cp my_app.jar
java -XX:SharedArchiveFile=my_app_cds.jsa -cp my_app.jar
```

### JEP 355: Text Blocks (Preview)

To solve the problem where defining multi-line strings in Java previously required workarounds using line-break escapes or concatenation operators, **triple double quotes** were introduced to define multi-line text.

Java 13 treats anything between two `"""` delimiters as part of the string, including newlines. Note: "two" here should be understood as "a pair"—one opening delimiter and one closing delimiter.

HTML style before Text Blocks were supported:

```java
String json ="{\n" +
              "   \"name\":\"mkyong\",\n" +
              "   \"age\":38\n" +
              "}\n";
```

HTML style after Text Blocks were supported:

```java
 String json = """
                {
                    "name":"mkyong",
                    "age":38
                }
                """;
```

SQL style before Text Blocks were supported:

```sql
String query = "SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`\n" +
               "WHERE `CITY` = 'INDIANAPOLIS'\n" +
               "ORDER BY `EMP_ID`, `LAST_NAME`;\n";
```

SQL style after Text Blocks were supported:

```sql
String query = """
               SELECT `EMP_ID`, `LAST_NAME` FROM `EMPLOYEE_TB`
               WHERE `CITY` = 'INDIANAPOLIS'
               ORDER BY `EMP_ID`, `LAST_NAME`;
               """;
```

For details on Text Block-related methods (`formatted()`, `stripIndent()`, `translateEscapes()`), please refer to the [API Enhancements - String Enhancements (Text Block-Related Methods)](#string-enhancements-text-block-related-methods) section in this article.

### JEP 354: Switch Expressions (Second Preview)

`Switch` expressions gained an additional keyword `yield` for exiting a `Switch` block, primarily used to return a value.

The difference between `yield` and `return` is that `return` exits the current method and returns a result, whereas `yield` exits the current `switch` expression branch and produces the value of that expression. A `switch` expression must cover all possible inputs, though a `default` branch is not necessarily required when all possible values have already been exhausted.

```java
 private static String descLanguage(String name) {
        return switch (name) {
            case "Java": yield "object-oriented, platform independent and secured";
            case "Ruby": yield "a programmer's best friend";
            default: yield name +" is a good language";
        };
 }
```

## API Enhancements

Not all API changes are delivered through a JEP (JDK Enhancement Proposal).

In the JDK development process, **JEPs** are typically used for major changes, such as introducing new language features (like `switch` expressions), new JVM mechanisms (like ZGC), or large-scale library refactorings. Operations like adding a few methods to an existing class, such as `String.indent()`, are usually treated as routine library maintenance. They are submitted and reviewed directly by JDK developers via **JBS (JDK Bug System)** tickets and then released directly with the version.

### String Enhancements

Java 12 added two new string-processing methods.

#### indent() - Indentation Method

The `indent()` method can be used to indent a string.

```java
String text = "Java";
// Indent by 4 spaces
text = text.indent(4);
System.out.println(text);
text = text.indent(-10);
System.out.println(text);
```

Output:

```plain
     Java
Java
```

#### transform() - Transformation Method

The `transform()` method can be used to transform a given string.

```java
String result = "foo".transform(input -> input + " bar");
System.out.println(result); // foo bar
```

### Files Enhancements

Java 12 added the `mismatch()` method to compare two files:

```java
public static long mismatch(Path path, Path path2) throws IOException
```

The `mismatch()` method compares two files and returns the position of the first mismatched byte, or `-1L` if the files are identical.

Code example (when the two files have identical contents):

```java
Path filePath1 = Files.createTempFile("file1", ".txt");
Path filePath2 = Files.createTempFile("file2", ".txt");
Files.writeString(filePath1, "Java 12 Article");
Files.writeString(filePath2, "Java 12 Article");

long mismatch = Files.mismatch(filePath1, filePath2);
assertEquals(-1, mismatch);
```

Code example (when the two files have different contents):

```java
Path filePath3 = Files.createTempFile("file3", ".txt");
Path filePath4 = Files.createTempFile("file4", ".txt");
Files.writeString(filePath3, "Java 12 Article");
Files.writeString(filePath4, "Java 12 Tutorial");

long mismatch = Files.mismatch(filePath3, filePath4);
assertEquals(8, mismatch);
```

### NumberFormat Enhancements

In Java 12, `NumberFormat` added support for formatting numbers in compact form:

```java
NumberFormat fmt = NumberFormat.getCompactNumberInstance(Locale.US, NumberFormat.Style.SHORT);
String result = fmt.format(1000);
System.out.println(result);
```

Output:

```plain
1K
```

### Socket API Enhancements

Java 13 rewrote the underlying implementation of the Socket API. `NioSocketImpl` is a drop-in replacement for `PlainSocketImpl`, using locks from the `java.util.concurrent` package instead of synchronized methods. To use the old implementation, pass `-Djdk.net.usePlainSocketImpl=true`.

Moreover, the new Socket implementation is used by default in Java 13.

```java
public final class NioSocketImpl extends SocketImpl implements PlatformSocketImpl {
}
```

### FileSystems Enhancements

In Java 13, three new methods were added to the `FileSystems` class to make it easier to use filesystem providers that treat the contents of a file as a filesystem:

- `newFileSystem(Path)`
- `newFileSystem(Path, Map<String, ?>)`
- `newFileSystem(Path, Map<String, ?>, ClassLoader)`

### String Enhancements (Text Block-Related Methods)

With Java 13 introducing the Text Blocks preview feature, the `String` class added 3 new methods to operate on text blocks:

- `formatted(Object... args)`: Similar to `String`'s `format()` method, added to support formatting of text blocks.
- `stripIndent()`: Used to remove leading and trailing spaces from each line in a text block.
- `translateEscapes()`: Converts escape sequences such as _"\\\t"_ into _"\t"_.

Because Text Blocks were a preview feature that could be removed in future versions, these new methods were marked as deprecated.

```java
@Deprecated(forRemoval=true, since="13")
public String stripIndent() {
}
@Deprecated(forRemoval=true, since="13")
public String formatted(Object... args) {

}
@Deprecated(forRemoval=true, since="13")
public String translateEscapes() {
}
```

For a detailed introduction to Text Blocks, please refer to the [JEP 355: Text Blocks (Preview)](#jep-355-text-blocks-preview) section in this article.

## Supplement

### About Preview Features

First, here is an excerpt from Oracle's official documentation: `This is a preview feature, which is a feature whose design, specification, and implementation are complete, but is not permanent, which means that the feature may exist in a different form or not at all in future JDK releases. To compile and run code that contains preview features, you must specify additional command-line options.`

In other words, a preview feature is one whose design, specification, and implementation are complete, yet it is not permanent—meaning it may exist in another form or not at all in future JDK releases. To compile and run code containing preview features, additional command-line options must be specified.

Taking `switch` expressions as an example, it began previewing in Java 12, continued to be refined in Java 13, and became a standard language feature in Java 14. Once standardized, its syntax and semantics became part of the Java SE specification and no longer require enabling preview features.

On one hand, this reflects the JDK's rigorous attitude as a standard platform when adding new features; on the other hand, I personally believe preview features should be adopted cautiously. Designing and implementing a feature is relatively straightforward, yet its real-world value still needs to be validated in actual use.

### JVM Optimizations

Every Java release is accompanied by optimizations to the JVM, including improvements to existing garbage collection algorithms, introduction of new garbage collection algorithms, and removal of legacy garbage collection algorithms that are no longer suitable today.

The overall direction of optimization is **efficient, low-latency garbage collection performance**.

Everyday application developers may pay more attention to new syntax features, whereas from a company's perspective, what matters more when considering whether to upgrade the Java platform is **JVM runtime improvements**.
